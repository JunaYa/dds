# 分析页：从记录汇总到可解释的日常分析

状态：待实施。测试入口方案待确认；尚未发布 issue 或添加 `ready-for-agent` 标签。

## Problem Statement

家长已经记录喂养、睡眠、尿布和生长数据，但当前分析页只展示最近 7 天的记录数量与类型计数，无法帮助他们理解宝宝的变化和规律。

记录可能存在漏记、补录、单位差异及跨午夜事件。直接求和、平均或套用健康标准，容易让家长把“已记录的数据”误认为宝宝全天的真实情况。

## Solution

将分析页设计为“结论 → 证据 → 原始记录”的阅读结构，回答：

- 最近与此前相比有什么变化？
- 已记录的喂养、睡眠和排便呈现什么规律？
- 哪些数据值得核对？
- 当前数据能支持哪些结论，还缺少什么？

首期覆盖喂养、睡眠、尿布和生长。所有结论均由可复算的统计规则生成，展示样本量、覆盖日期及计算口径。数据不足时展示事实与分布，不强行生成判断。

## User Stories

1. 作为家长，我希望只分析当前选中宝宝的数据，以免不同宝宝的记录混在一起。
2. 作为家长，我希望切换宝宝后分析同步更新，以便分别了解每个宝宝。
3. 作为家长，我希望先看到少量有依据的变化摘要，以便快速了解近期情况。
4. 作为家长，我希望查看摘要对应的图表和记录，以便核对结论。
5. 作为家长，我希望知道每个指标包含多少次有效记录、覆盖哪些日期，以便判断信息是否充分。
6. 作为家长，我希望漏记日期与零值明确区分，以免误解趋势。
7. 作为家长，我希望未结束的今天单独标识，以免与完整一天比较。
8. 作为家长，我希望比较最近两个完整的 7 天周期，以便了解短期变化。
9. 作为家长，我希望奶瓶、亲喂和辅食分开分析，以便理解不同喂养方式。
10. 作为家长，我希望查看每日已记录奶瓶奶量和单次奶量分布，以便了解变化。
11. 作为家长，我希望查看已记录喂养之间的间隔，以便观察日常节奏。
12. 作为家长，我希望查看亲喂次数、时长及左右侧分布，以便回顾亲喂情况。
13. 作为家长，我希望亲喂时长不被换算成奶量，以免得到没有依据的结果。
14. 作为家长，我希望查看每日已记录睡眠时长和日夜分布，以便观察睡眠安排。
15. 作为家长，我希望跨午夜睡眠被正确分配到对应日期，以免每日时长失真。
16. 作为家长，我希望查看单次睡眠时长与入睡时间分布，以便观察作息规律。
17. 作为家长，我希望进行中的计时与已完成睡眠分开，以免统计不断变化。
18. 作为家长，我希望分别查看换尿布、排尿和排便的记录趋势，以便回顾变化。
19. 作为家长，我希望混合尿布不会导致换尿布总次数重复计算，以便信任统计。
20. 作为家长，我希望查看体重和身长的实际测量轨迹，以便了解长期变化。
21. 作为家长，我希望看到两次测量的日期间隔和增量，以免把不同间隔的变化直接比较。
22. 作为家长，我希望可疑录入值提示我核对，以便及时修正错误。
23. 作为家长，我希望统计离群值不会被自动删除或解释为疾病，以便保留真实记录。
24. 作为家长，我希望没有足够数据时明确说明原因，以便知道还能记录什么。
25. 作为家长，我希望编辑、删除、恢复记录后分析立即更新，以便看到一致的信息。
26. 作为家长，我希望在手机、桌面和中英文环境下都能读懂分析，以便持续使用。
27. 作为使用辅助技术的家长，我希望图表提供文字摘要和数据明细，以便获取同样的信息。

## Implementation Decisions

### 范围与页面结构

- 保留现有“分析”导航入口和宝宝选择机制。
- 页面依次展示变化摘要、分项分析、数据覆盖及口径说明。
- 首期实现喂养、睡眠、尿布、生长；其他记录项保留为后续扩展。
- 每条摘要关联参与计算的原始记录；展开明细不改变记录数据。

### 分析模块

- 建立功能域内的纯分析模块，接收当前宝宝记录、记录类型定义和本地日期，返回指标、比较结果、样本覆盖、排除原因及来源记录标识。
- 页面负责展示与交互，不在界面中重复实现统计公式。
- 计算在本地完成，不引入外部 AI 服务，不上传家庭记录。
- 首期不修改持久化结构；无法由现有字段可靠计算的指标不展示。
- 按稳定的类型与字段标识识别含义，同时检查字段类型和单位。用户修改定义后，不得继续套用不匹配的规则。

### 时间与缺失数据

- 周期比较默认使用截至昨天的最近 7 个完整本地自然日，以及再之前的 7 日；今天单独展示为“进行中”。
- 已有事件时间用于分析，不按录入先后顺序推断事件发生顺序。
- 未来事件不进入当前观察周期。
- 缺失值和缺失日期不填零；合法的零值与缺失值分别处理。
- 覆盖天数只表示有相关记录的日期数，不宣称记录完整。
- 首期不提供“完整记录日”确认功能，因此所有总量使用“已记录”措辞。

### 喂养

- 奶瓶奶量、亲喂时长、辅食分别计算，不跨方式合计。
- 仅对单位明确且可兼容的奶量求和；缺少奶量的记录不按零处理。
- 单次奶量与喂养间隔使用中位数及四分位区间描述。
- 喂养间隔标为“相邻已记录喂养间隔”；展示有效间隔数，避免暗示漏记期间没有喂养。
- 左右侧时长以结构化亲喂计时数据为依据，不将分钟换算为摄入量。

### 睡眠

- 优先确认现有记录时间代表开始还是结束，再结合时长构建区间；无法确认时不生成区间分析。
- 有可靠区间时按本地午夜切分；重叠区间的总时长取并集，并提示核对。
- 日夜构成优先使用明确的睡眠类型；未知类型单独列示。
- 不从稀疏睡眠记录推断夜醒次数、清醒窗口或整夜连续睡眠。
- 入睡时间按跨午夜的时钟数据处理，避免将 23:50 与 00:10 算作中午附近。

### 尿布与生长

- 换尿布总次数与排尿、排便指标分别计算。
- 混合尿布可同时计入排尿和排便；换尿布总次数只计一次对应次数。
- 缺少有效次数字段时展示记录条数，不静默假定每条等于一次。
- 生长展示原始测量点、测量间隔和增量；缺失测量保留为空缺，不插补成实测值。
- 首期不叠加 WHO 百分位或 Z 分数曲线，不生成生长健康评级。

### 统计与结论

- 优先使用中位数、四分位区间、时间分布及等长周期比较。
- 比较结果同时展示绝对变化和两个周期的样本覆盖；基准为零时不计算百分比。
- 数据充分性阈值属于产品规则，实施前需通过代表性数据验证并明确记录，不包装为医学标准。
- 阈值未确定或数据不满足条件时，只展示描述性结果。
- 不使用“显著改善”“异常健康”等缺乏检验或临床依据的措辞。
- MAD 等离群检测仅作为后续候选方法；首期优先处理明确的数据冲突，不引入未经校准的自动告警。

## Testing Decisions

以下测试入口方案待确认：以现有完整应用交互入口为主，预置工作区，通过真实导航进入分析页，验证用户可见的摘要、数据口径、宝宝切换及明细。对难以通过页面穷举的统计边界，在纯分析模块公共入口补充输入输出测试。

- 沿用现有应用流程、工作区状态、宝宝切换和 iOS 导航测试的组织方式。
- 只测试外部行为，不测试内部辅助函数、组件状态或具体 DOM 布局。
- 关键场景包括：
  - 不同宝宝隔离，编辑、删除、恢复后结果更新。
  - 空数据、单条数据、缺失字段、零值及不兼容单位。
  - 今天未结束、周期边界、未来记录及跨午夜睡眠。
  - 重叠睡眠、进行中计时、午夜附近入睡时间。
  - 混合尿布不重复计入换尿布总次数。
  - 奶瓶与亲喂分离，缺少奶量不补零。
  - 生长测量缺失与不等间隔。
  - 数据不足时不生成变化判断。
  - 摘要、图表及原始记录之间数值一致。
- 界面验证覆盖中英文、窄屏与桌面、浅色与深色、键盘访问及图表文字替代。
- 执行 UI 边界检查、类型检查及相关测试。此前发现的页面标题测试失败需在实施时重新核对并单独记录，不能作为本功能通过的证据。

## Out of Scope

- 健康总分、疾病诊断、治疗或喂养剂量建议。
- 下一次喂养或睡眠的预测。
- 将相关性解释为因果关系。
- WHO 生长标准接入及为此新增的宝宝资料。
- 疫苗缺针判断、补种建议、维生素剂量及漏服判断。
- 自定义记录的通用分析规则引擎。
- 自动补齐缺失数据、自动删除离群记录。
- 云端分析和外部 AI 总结。

## Further Notes

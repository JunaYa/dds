# Little days 产品定义

Little days 是陪伴家庭从怀孕、分娩到育儿的记录应用。单手就能记下刚发生的事，随时找回准确的记录，并从自己的数据中看清变化。

产品以便捷记录为核心，支持离线使用、可核对的分析和用户可掌控的数据。妈妈与孩子都是独立的记录对象；孕期记录在孩子出生后继续保留。育儿首期覆盖 0–6 岁，不因超过年龄范围锁定或删除历史。

本文定义后续产品方向和验收要求，不代表以下能力已全部实现。当前实现范围见根目录 README；既有应用入口决策继续有效，原先仅面向儿童的产品范围由本文扩展。

## 使用场景与取舍

主要使用者是孕期妈妈及日常照护者。典型场景包括夜间单手记录喂养、产检后补录测量、家人接班前查看最近一次照护，以及就诊前整理一段时间的记录。

功能冲突时，优先保证记录正确保存，再减少操作，随后增加分析深度。首页空间优先留给记录和最近状态。社区、商城、内容推荐和积分不进入首期范围；家庭用品管理保留为辅助工具，不占主导航。

## 连续的家庭档案

家庭中可以有多个妈妈档案、多个孕次和多个孩子。每条记录明确属于谁；一段孕期可以关联多个孩子。切换对象时，正在进行的计时仍属于原对象。

| 阶段 | 核心记录 | 首页优先呈现 |
| --- | --- | --- |
| 孕期 | 产检日期与结果、体重、身体感受、胎动记录、备注 | 当前孕期、常用记录入口、最近记录、用户设置的待办 |
| 分娩 | 宫缩起止、入院事件、出生时间、出生测量、分娩经过 | 大按钮计时、最近事件、出生信息入口 |
| 产后 | 妈妈的恢复感受、测量、泵奶、就诊记录 | 妈妈自己的近期记录，以及宝宝记录切换入口 |
| 育儿 | 母乳与瓶喂、睡眠、尿布、成长、辅食、疫苗及用药记录、成长事件 | 进行中的计时、上次记录、今日汇总、常用记录入口 |

用户可以从任意阶段开始，无须补齐以前的经历。创建孕期档案可只填昵称，预产期可以稍后补充；直接开始育儿时允许生日暂缺，缺失时不推算年龄。孕周显示需要明确的计算依据，修改依据保留变更记录。

出生流程由用户确认实际出生信息，创建或关联宝宝档案。预产期到达不自动转为已出生。支持多胎、再次怀孕，以及结束或归档孕期但不建立宝宝档案；不强迫填写结束原因。妈妈的产后记录和宝宝的育儿记录可以同时进行。

## 便捷的验收标准

以下数字是设计与测试目标，尚未测得。测试起点为已经打开首页、选定记录对象；保存终点为本地持久化成功，首次建档和系统授权另计。

| 操作 | 目标 |
| --- | --- |
| 开始喂养、睡眠或宫缩计时 | 首页一次点击开始，立即显示对象和计时状态 |
| 结束计时 | 一次点击停止并保存，随后可以修改或撤销 |
| 记录一次常用尿布类型 | 两次点击以内完成，不要求输入备注 |
| 记录瓶喂量或体重 | 一个紧凑表单，只填必要值，目标十秒内保存 |
| 查看上次喂养及今天的记录概况 | 首页可见，无须先打开分析页 |
| 补记或纠错 | 在同一表单改发生时间、数值或对象，不必删除重建 |

默认发生时间为现在，但保存前可以修改。记住常用选项与单位；上次的测量值只能作为参考，不能默认为本次实测值。所有非必要字段折叠，用户无需先学习自定义类型系统。

快捷入口随阶段变化，允许固定常用项目并保持顺序稳定。保存后明确显示成功，失败时保留输入并允许重试。离线成功保存无需等待联网；同步状态另外展示。首次使用不要求注册账号。

手机交互以单手操作为主，支持大字体、屏幕阅读器和深色模式。计时在锁屏、切后台、退出重开后仍可恢复。小组件与系统快捷操作在核心流程稳定后加入。

## 页面与导航

主导航保持四项：今天、记录、分析、我的。记录入口在今天页直接可用，不再增加一个必须经过的表单选择页。

- 今天：顶部明确当前对象与阶段，其次是进行中的计时、常用记录、上次记录和今日概况。没有记录时提供入口，不显示虚构数据。
- 记录：按时间查看、搜索、筛选和编辑；可以只看妈妈、某个孩子或按家庭时间线查看，每条记录保留归属标识。
- 分析：按对象、指标和日期范围查看汇总与趋势，点击统计可以回到原始记录。
- 我的：家庭档案、阶段管理、备份恢复、同步与共享、语言外观、辅助用品管理及自定义记录。

手机优先保证快速输入；平板和桌面可同时展示记录入口与历史列表，便于核对、补记和导出。

## 记录准确

每条记录保留稳定标识、记录对象、发生时间、创建时间、更新时间、来源和数据版本。手动输入、计时生成和导入的数据可以区分；共享开放后再记录操作者。

发生时间与录入时间分别保存。时间点保存时区信息，生日、预产期等纯日期不经时区转换。跨时区后保留原始时间信息，按所选统计时区归日。旧记录缺少时区时明确标记未知，迁移不伪造精度。

测量值必须带单位，换算不覆盖原始值。缺失、零值、估计值和进行中的记录分开处理。不能将母乳时长推算成摄入量，也不能将辅食重量计入奶量。

禁止保存不存在的日期、无效数字和结束早于开始的时段。对可疑重复、重叠时段或显著偏离历史的输入，提供核对提示，不擅自修改用户记录。无需临床阈值即可完成格式、单位和时序校验。

重复点击或重试不会生成重复记录。纠错保留修订依据，普通删除可撤销；彻底删除及其对修订历史、备份和共享副本的影响必须明确。导入先预览重复与冲突，用户确认后再写入。

## 分析回答具体问题

首期分析使用确定的统计规则，在本机完成。先回答今天记录了多少、上次记录距今多久，以及近 7 天或 30 天的变化。分析页展示日期范围、单位、有效记录数和更新时间。

| 指标 | 统计口径 |
| --- | --- |
| 喂养 | 区分瓶喂量、母乳左右侧时长和辅食记录，不合并为一个摄入量 |
| 睡眠 | 汇总已结束时段；跨日按重叠时长拆分，重叠时段不重复累计；进行中单独显示 |
| 尿布 | 按记录的事件次数及类型统计，未记录不能解释成没有发生 |
| 体重与身高 | 分别展示带单位的实测时间点、相邻变化和测量间隔 |
| 孕期及产后测量 | 显示原始趋势与备注，孕期和产后可以分段查看 |
| 宫缩 | 展示每次持续时间与相邻起始时间间隔，供用户回顾 |

删除或修正记录后重新计算。没有记录显示暂无数据；对比期缺失时不生成增长率。对比均值展示分母与有记录的天数，不能默认为未记录日的值是零。示例文案为“今天已记录瓶喂 4 次，共 360 mL”，避免写成“宝宝今天只喝了 360 mL”。

统计与趋势必须能追溯到参与计算的记录。首期不输出诊断、药物剂量、分娩时机判断或没有依据的风险评分。参考曲线、临床阈值和医学解释如以后引入，需单独明确来源、适用范围与审核流程。

## 数据安全与恢复

本地优先意味着断网也能完成核心记录。用户可以只在本机使用；云同步、家庭共享和外部 AI 处理均不默认开启。诊断日志不得包含身体记录、姓名、照片或用户备注。

正式承载长期数据前，必须交付加密的持久化存储与可恢复备份。密钥使用平台安全存储，不能与明文数据或解密密码放在同一份文件里。数据库、附件和备份分别明确加密与密钥恢复方案；在完成设计及平台验证前不承诺端到端加密。

备份页展示最近成功备份时间、位置和恢复方式。用户可导出可移植的数据；明文导出前明确其不受应用加密保护。恢复先校验格式、版本和完整性，提供预览；恢复或迁移失败时保留原数据。不能把仅存在同一设备内的副本当作防丢失备份。

跨设备同步需要独立建设身份认证、传输保护、授权撤销和冲突处理。界面区分已保存到本机、待同步、同步完成和同步失败，冲突不得静默覆盖记录。家庭共享按成员配置查看或编辑权限；撤销共享后说明已导出的副本无法远程收回。

彻底删除覆盖活动数据与附件，明确备份保留规则及删除传播状态。离线设备重新连接时不得复活已删除数据。应用锁可以减少他人直接查看的机会，但不能代替存储加密。

## 多平台交付

| 平台 | 主要任务 | 验收重点 |
| --- | --- | --- |
| iOS、Android | 随手记录、单手计时、补记 | 离线、后台恢复、输入法、大字体、系统日期与时间行为 |
| macOS、Windows、Linux | 核对历史、批量整理、导出分析 | 键盘操作、窗口缩放、大量记录与文件备份恢复 |
| Web | 便捷访问及浏览器内记录 | 存储限制、清理风险提示、离线与导出能力的实际可用性 |

各平台共用记录语义与统计规则，允许布局适应设备。平台是否可用、是否通过发布验收、是否支持同步分别说明。使用 Tauri 或共用代码不等于所有平台均已验证。

同步上线后，以手机记录、桌面查看与修正、手机接收修正作为跨平台验收路径，并覆盖断网补写、并发编辑和删除冲突。

## 实施顺序与现有代码

截至本次定义，正式入口为 `src/features/little-days/`，已有儿童档案、照护记录、自定义类型、用品、计时恢复和中英文界面。数据模型要求每条记录属于一个孩子，档案要求生日；存储为 `little-days.workspace.v1` localStorage。孕期与妈妈档案、趋势分析、加密存储、备份恢复和云同步均未实现。

1. 建立连续档案和数据保护基础。增加妈妈、孕次、宝宝及关系，设计版本迁移，先提供导出与恢复，再交付加密持久化。保留已有记录标识、归属、单位和计时状态；迁移前保留可恢复副本，失败不覆盖旧数据。
2. 完成各阶段的常用记录和今天页。减少字段与步骤，完成出生衔接、妈妈与宝宝切换、离线保存和计时恢复。按便捷标准实测，用品与类型配置移入辅助入口。
3. 交付可核对的分析和就诊摘要导出。覆盖缺失数据、跨日时段、重叠记录、单位换算及修改后的重算；摘要明确对象与时间范围。
4. 逐平台验收并发布。移动端优先验证日常输入，桌面端验证查询和恢复，明确 Web 的数据保存边界。同步与家庭协作在本地核心可靠后单独交付。
5. 根据真实使用再增加小组件、提醒、语音或识别录入。识别结果经用户确认后写入，不把识别输出直接当成准确记录。

产品验收同时观察常用记录耗时、操作次数、保存失败与恢复结果、误录后纠正成本，以及统计能否与原记录对上。默认使用本地测试和用户同意的研究，不为统计产品指标上传照护内容。

每次功能交付沿用 `packages/ui` 与 `packages/iconography` 的公共组件，并执行 `pnpm check:ui`、类型检查和相关测试。持久化改动必须覆盖迁移与恢复；平台能力必须在对应环境验证后才标记为已支持。
